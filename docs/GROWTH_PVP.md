### 2026-09-13 战斗弱网验证

运行 `npm run test:performance -- tests/performance/growth-combat.spec.ts`。生产 Chromium 渲染 1 个客户端，另有 7 个认证脚本客户端，三职业在沿岸研究站进行据点战。8 条 WebSocket 连接均通过双向各 100～140ms 延迟、每 5 秒一次约 500ms TCP 有序停顿；代理使用单向 FIFO，避免定时器误把有序 TCP 模拟成乱序传输。

仅初始 XP 使用服务端夹具加速；移动、射击、技能、手雷、刷新和选择都经过实际网络。八人各选四次，7 个故意过期选择全部拒绝，未发现他人候选/池/Perk 泄露。该次记录共 450 次射击、112 次命中；20 秒采样推进 603 帧，收到 2490 份快照。服务器模拟 P95 0.575ms / P99 0.945ms，最大消息 15116 字节。浏览器帧间隔 P95/P99 约 33.4ms，不能宣称稳定 60 FPS。报告：`artifacts/qa/growth-combat-performance.json`；截图同名 PNG。

这些数据覆盖此 Windows 主机上的脚本战斗及 TCP 停顿恢复，不等于八台渲染设备、物理丢包测试或真人平衡验收。消息体积明显大于静止基线，但两者负载不同，不能据此直接归因于成长系统。选卡界面新增服务器确认等待状态；请求处理中禁用同批候选和刷新，收到新批次后恢复，连接错误允许重试。

试玩日志现已使用独立参赛记录保存离场者的等级、经验、死亡及选卡耗时，机器人数量单独记录。浏览器测试验证主动离场、角色移除后统计仍完整。

## P1 历史规则（后续已扩展，见上述当前阶段）

- 从联机大厅点击「创建成长试玩房间（P1）」，其他玩家输入房间码加入。需要联网账号，每房间1～8个真人席位；单人自动补一名同配装训练机器人，多人开局不补机器人；所有人准备后开始，晚加入先观战。
- 仅团队交火，使用现有地图。固定15分钟，按击杀分判胜负，平分为平局；退出导致一队无人时提前结束；单人训练的机器人算作对方队伍，观战者离开不会终止训练，唯一真人席位离开后结束。禁用经典模式短局目标分。
- 全员独立 `assault` 身份，生命100，瞄准0.7，弹药系数0.9；主M4、副USP、2枚手雷。基础枪参数来自独立配置，复活恢复相同参数。展示复用突击兵素材，不继承其被动。
- 不读取训练点、旧职业等级和装备解锁；不允许成长房间修改旧配装。新模式暂不发放任何账号奖励，也不迁移或写入旧资产。
- 击杀100 XP；最近8秒造成实际伤害的其他敌方攻击者获得60助攻XP。护盾/出生保护未造成伤害不记贡献，死亡结算只发生一次。
- 累计XP阈值为0 / 200 / 450 / 800 / 1200，对应Lv1～Lv5。目标升级时间2/4/7/10分钟仍需真人数据调节，不是按时间赠送升级。
- 普通池固定8项，全员开放；每级3张不同候选，排除已选；同时只有一组候选。连续升级顺序排队，每局最多选四项。
- 每局1次刷新，重新抽3项，允许出现上次未选的牌。刷新生成新批次，旧批次请求失效。
- 可「稍后选择」再展开；不暂停战斗，死亡期间可选。服务器确认后更新Build，客户端不乐观增加升级或经验。
- 死亡保留等级、经验、已选升级、未选候选和剩余刷新；清除临时加速与主动持续效果。技能和Ultimate触发冷却继续计时，防止死亡刷新冷却。
- 第12分钟全员开放Berserker，不占四次普通升级，无额外选卡。下一局恢复Lv1、零XP和一次刷新。

### 主动技能与升级表

时间均以30Hz模拟帧计算，以下数值为项目设计，非原作还原结论。

| 能力 | 触发与效果 | 代价 / 叠加 / 反馈 |
| --- | --- | --- |

| Tactical Reload | 非空仓手动换弹时间×0.8 | 空仓无效；影响当前换弹计时 |
| Scavenger | 距敌方尸体80像素内补充当前枪半弹匣备弹 | 每人每次死亡可拾一次，不超备弹容量；补给音效 |

## 接口、恢复与信任边界

- 创建请求：`{type:'create', rules:'growth', ...}`；省略规则保持经典模式。房间规则开局后不可变更。
- 选择：`{type:'growthChoice', roomId, round, batch, upgrade}`；刷新使用 `growthReroll` 和相同对局/批次标识。
- actor归属由连接绑定，忽略客户端自报actor；验证当前局次、运行状态、候选批次、可选ID及刷新余额。重复、跨局、过期、观战者选择均不能改变状态。
- 私有候选仅附在收件人自己的 `StateMessage.growth`；公开角色只含新职业、等级和Ultimate标记。内部攻击者贡献与选卡统计不广播。
- Battle Checkpoint包含成长状态及随机源，MatchSession继续保存控制器。相同检查点、相同输入在同运行时恢复一致。
- 页面保留的断线凭据在30秒内恢复席位、候选和选择。服务器进程重启仍不恢复活动房间，不把内存检查点称为持久化对局。
- 内容指纹包含成长规则、武器配置、升级目录与Ultimate说明；旧客户端与新服务端拒绝混用。
- 服务端结算日志 `growth.playtest_result` 记录对局ID、匿名actor、击杀/死亡、等级/经验和选择耗时，不记录密码或会话。人离场后若actor被移除，该玩家末局记录可能缺失，P3持久结算前需补全独立参赛记录。

## 单人试玩修复

成长房间现支持一个账号开局：创建房间 → 准备 → 开始单人试玩（对战机器人）。系统自动添加一名同属性、同武器的Assault训练机器人，不占真人席位；机器人正常移动、射击、复活并自动选择成长升级。击杀机器人同样获得经验。后来加入的真人先观战，返回大厅后多人开局不保留机器人。经典PvP仍要求至少两人。

新增单浏览器开局、机器人击杀触发选卡、AI射击/自动升级、重连、观战离开、下局真人替换及单人席位退出回归。此修复不表示真人平衡验收已完成。新旧服务端内容版本不同，需要使用本次配套服务端。
