## P1 可执行规则

- 从联机大厅点击「创建成长试玩房间（P1）」，其他玩家输入房间码加入。需要联网账号，每房间2～8席；所有人准备后开始，晚加入先观战。
- 仅团队交火，使用现有地图。固定15分钟，按击杀分判胜负，平分为平局；退出导致一队无人时提前结束。禁用经典模式短局目标分。
- 全员独立 `assault` 身份，生命100，瞄准0.7，弹药系数0.9；主M4、副USP、2枚手雷。基础枪参数来自独立配置，复活恢复相同参数。展示复用突击兵素材，不继承其被动。
- 不读取训练点、旧职业等级和装备解锁；不允许成长房间修改旧配装。新模式暂不发放任何账号奖励，也不迁移或写入旧资产。
- 击杀100 XP；最近8秒造成实际伤害的其他敌方攻击者获得60助攻XP。护盾/出生保护未造成伤害不记贡献，死亡结算只发生一次。
- 累计XP阈值为0 / 200 / 450 / 800 / 1200，对应Lv1～Lv5。目标升级时间2/4/7/10分钟仍需真人数据调节，不是按时间赠送升级。
- 普通池固定8项，全员开放；每级3张不同候选，排除已选；同时只有一组候选。连续升级顺序排队，每局最多选四项。
- 每局1次刷新，重新抽3项，允许出现上次未选的牌。刷新生成新批次，旧批次请求失效。
- 可「稍后选择」再展开；不暂停战斗，死亡期间可选。服务器确认后更新Build，客户端不乐观增加升级或经验。
- 死亡保留等级、经验、已选升级、未选候选和剩余刷新；清除临时加速与主动持续效果。技能和Ultimate触发冷却继续计时，防止死亡刷新冷却。
- 第12分钟全员开放Berserker，不占四次普通升级，无额外选卡。下一局恢复Lv1、零XP和一次刷新。

### 主动技能与升级表

时间均以30Hz模拟帧计算，以下数值为项目设计，非原作还原结论。

| 能力 | 触发与效果 | 代价 / 叠加 / 反馈 |
| --- | --- | --- |
| Combat Roll | E发动，12帧移动速度×1.5，冷却240帧 | 期间不能射击；仍受伤与碰撞约束；蓝色爆发、技能音效及冷却HUD |
| Momentum | 击杀后90帧移动速度×1.2 | 再次击杀刷新，不累加；死亡清除；HUD显示加速中 |
| Tactical Reload | 非空仓手动换弹时间×0.8 | 空仓无效；影响当前换弹计时 |
| Scavenger | 距敌方尸体80像素内补充当前枪半弹匣备弹 | 每人每次死亡可拾一次，不超备弹容量；补给音效 |
| Grenade Pouch | 选择时立即增加1枚手雷 | 一次性；复活不补；HUD数量更新 |
| Controlled Burst | 蹲伏且静止，散布×0.65 | 离开条件立即恢复；与Last Stand取较低散布系数，不相乘 |
| Quick Hands | 持续移动时，每3帧额外推进1帧换弹 | 必须实际移动，静止不生效；不增加弹药；可与战术换弹组合 |
| Last Stand | HP低于25%，散布×0.6 | 恢复至阈值立即失效；不增加生命、伤害或护甲 |
| Slide Reload | 发动翻滚时从当前枪备弹转移最多3发到弹匣 | 不超弹匣、不生成弹药；可在换弹中使用，保留换弹流程 |
| Berserker | 开放后击杀恢复15生命、加速90帧 | 触发冷却150帧；与Momentum加速取最大值；橙色爆发、觉醒说明 |

P1 可比较的两条四选路线：推进型（Momentum、Quick Hands、Slide Reload、Scavenger）；阵地型（Tactical Reload、Controlled Burst、Last Stand、Grenade Pouch）。测试组合改变的是移动/换弹/风险决策，不能凭能力数量证明玩法已成立。

## 接口、恢复与信任边界

- 创建请求：`{type:'create', rules:'growth', ...}`；省略规则保持经典模式。房间规则开局后不可变更。
- 选择：`{type:'growthChoice', roomId, round, batch, upgrade}`；刷新使用 `growthReroll` 和相同对局/批次标识。
- actor归属由连接绑定，忽略客户端自报actor；验证当前局次、运行状态、候选批次、可选ID及刷新余额。重复、跨局、过期、观战者选择均不能改变状态。
- 私有候选仅附在收件人自己的 `StateMessage.growth`；公开角色只含新职业、等级和Ultimate标记。内部攻击者贡献与选卡统计不广播。
- Battle Checkpoint包含成长状态及随机源，MatchSession继续保存控制器。相同检查点、相同输入在同运行时恢复一致。
- 页面保留的断线凭据在30秒内恢复席位、候选和选择。服务器进程重启仍不恢复活动房间，不把内存检查点称为持久化对局。
- 内容指纹包含成长规则、武器配置、升级目录与Ultimate说明；旧客户端与新服务端拒绝混用。
- 服务端结算日志 `growth.playtest_result` 记录对局ID、匿名actor、击杀/死亡、等级/经验和选择耗时，不记录密码或会话。人离场后若actor被移除，该玩家末局记录可能缺失，P3持久结算前需补全独立参赛记录。

## 验证与性能基线

变更前 `npm run check`：71个测试文件、410项单元测试通过；共享模拟依赖边界通过。历史README中的测试数量不是本次结果。

本次最终检查：`npm run check` 73个文件、425项单元测试通过；3项相关浏览器回归通过；4项生产离线测试通过；八客户端成长性能用例通过（不含60 FPS承诺）；隔离目录服务端启动、版本、账号持久化与校验通过。

最终本地发行：内容版本 `2ea1cea6c1c0b28e`，ZIP约36.1MB，校验228个文件。最新ZIP SHA256：`42f2d967b61cfaa9479867c5ddf4c82240cbcec0b38172d9aa07cef4965a9921`。历史发行保留在 `artifacts/releases/`，最新路径与校验值由 `artifacts/friends-latest.json` 记录。

新增单元/网络测试覆盖成长隔离、击杀助攻、候选权限、刷新、死亡选择、补给、手雷袋、翻滚装填、换弹、Ultimate冷却、8控制器、检查点一致性及旧账号奖励不变。

双浏览器测试覆盖创建/加入/准备、仅本人收到候选、暂存选择、刷新、死亡选卡、断线恢复和跨局重置。通过服务器测试夹具加速经验与结算；没有产品内作弊XP接口。这些测试不能冒充真人自然对局。

可复现命令：

```powershell
npm run check
npx playwright test tests/gameplay/growth.spec.ts tests/gameplay/online.spec.ts tests/gameplay/weak-network.spec.ts
npx tsx tools/growth-benchmark.ts
npm run release
npm run test:performance -- tests/performance/growth.spec.ts
```

同进程、8静止控制器、预热300帧后采样2100帧：经典P95约0.065ms，成长P95约0.064ms；公开快照3420→3892字节，个人成长额外184字节。报告为 `artifacts/qa/growth-baseline.json`；微基准差值不代表成长模式更快。

Windows生产浏览器、1渲染客户端+7认证WebSocket客户端、8人同时待选：15秒推进453帧，收到1610份快照，无候选泄露；服务器模拟P95约0.56ms、P99约0.87ms；最大消息3003字符。浏览器帧间隔P95约50ms、P99约66.6ms，**未达到60 FPS验收**。报告为 `artifacts/qa/growth-performance.json`，该数据不覆盖激烈战斗、跨设备网络或完整8人真人对局。

既有弱网用例原来在检查服务器开火后轮询瞬时弹道，可能错过33～100ms可见窗口；现在在浏览器内记录曾经可见，再独立验证停流后消失，保留原始行为断言。

## 试玩、发行与后续

本地发行执行 `npm run release`，生成带运行环境的Windows x64朋友ZIP、配套服务端及离线检查结果；保留时间戳版本和latest。源码和研究文档不进入朋友包。

1. 完整解压 `artifacts/Project-Strike-Windows-latest.zip`，双击 `PLAY.cmd` 进入联网大厅；`SOLO.cmd` 仍是原离线战役。
2. 新规则必须连接本次配套服务端，公网没有自动部署。本机开发者可执行 `npm run server`，或启动 `artifacts/project-strike-server/START.cmd`，填写 `ws://127.0.0.1:4180`。
3. 两台设备试玩时，房主按配套服务端README配置局域网监听，朋友填写房主局域网IP。不要把自己的127.0.0.1发给另一台电脑。
4. 注册/登录测试账号，创建成长试玩房间、分享房间码、双方准备并开始。

真人记录表：每局记录人数、时长、职业/选择组合、首次升级时间、最终等级差；每位玩家回答「选卡是否需要思考」「是否改变打法」「后期是否更有高潮」「是否想再试其他Build」，附一个具体例子。至少完成P1两人自然对局并分析反馈后再启动P2；完整MVP在P4累计两轮、建议20局后验收。

仍未完成：真人P1验证、第二/第三职业、据点成长及追赶、基础Perk/自选成长池、账号成长持久化、全战斗性能与P4/P5。没有对这些阶段做完成声明。
