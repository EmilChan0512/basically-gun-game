# Phase 3：自研游戏基础战斗沙盒

2026-09-11：按用户新方向执行。目标从完全复刻转为在已有机制基础上打造 Project Strike，先建立熟悉的移动与射击节奏，再迭代自己的风格与内容。旧逐帧复刻规格归档于 [历史规格](PHASE_3_REPLICA_ARCHIVE.md)，不再作为本阶段退出门槛。

## 本阶段范围

- 默认入口整合30Hz移动、起步/制动/空中操控、蹲伏、起跳、攀爬和实心地形碰撞。
- USP半自动与M4自动射击，共享射击冷却、独立有限弹药、手动/自动换弹和切枪取消换弹。
- 枪口偏移、散布/后坐力、射程、遮挡、站/蹲命中框、基础头部/暴击伤害。
- 玩家与靶子的伤害、死亡、出生保护、回血、复活及玩家弹药恢复。
- 可读的生命/弹药/换弹/复活HUD，短暂弹道、靶子生命条、伤害与击杀反馈。
- 暂停、单步、慢速、失焦清输入、四个测试站和JSON导出；旧120Hz实验室作为独立调参入口保留。

沿用已查证的基础参数和实现，不为了摆脱“复刻”名称重写已有模块。`Original*`文件名暂时保留，表示实现来源，不表示后续规则不能修改。当前角色采用85HP和0.9弹药倍率配置，尚无职业选择系统。

## 参考方式与证据边界

优先在现有实现上迭代。只有具体机制问题需要时才检查已有反编译脚本或P-code。运行老游戏或逐帧采集必须确有必要，并先询问用户；本轮没有运行老游戏。

保留 EXTRACTED / INFERRED / OBSERVED / TUNED 分类，现有63条证据不因方向变更升级。关卡布局、反馈持续24帧、弹道显示3帧、840px掉落死亡边界和复活清除回血延迟是本项目实现选择，不作为新增原版事实。场景击杀数来自靶子累计死亡次数，跨玩家复活保留，R重置清零。

## 后续边界

移动中的手臂姿态、动画与声音仍是灰盒；跨Flash帧事件排序未做原版运行观测。水域、全部职业/技能/装备/异常状态、完整地图、多机器人与3v3对局不属于本次基础闭环验收。

下一阶段先在这套移动和枪械基础上加入一个能移动、寻敌、攻击的对手，再扩到小规模对局。AI可按本项目体验目标设计，有具体疑问时再参考旧代码，不再把全量反编译或老游戏逐帧测量设为前置条件。
