# 成长模式真人试玩记录

目的：验证选卡是否值得思考、组合是否改变打法、后期是否更有高潮、是否愿意再试另一套构筑。自动客户端和单人机器人结果不能计作多人真人体验结论。目前尚未收集本阶段的真人结果。

当前基线：2026-09-14，成长v3四干员、rules57，内容指纹`cba07e76033db59b`。以[开发规格](COMBAT_DEVELOPMENT_SPEC_V1.md)为数值依据；后续换包时按包内manifest填写实际指纹，不能继续沿用本段旧值。机器人、浏览器及性能证据及各自对应版本见[执行记录](COMBAT_V3_IMPLEMENTATION.md)，本表仍为空白真人记录。

## 准备

解压最新 Windows 包，双击 `PLAY.cmd`，连接同一配套服务器。注册或登录后创建成长房间，其他玩家凭房间码加入。单人可先直接开局练习；多人开局前全员准备。房间里的“第一次玩成长模式”说明提供各职业的两条尝试路线。

记录双方确认的内容版本、地图、模式、实际真人人数、是否含机器人。使用匿名玩家代号，不记录密码、账号令牌或真实姓名。不同内容版本分别统计。

## 第一轮：理解规则与组合差异

四干员同时纳入：突击兵、重装兵、狙击手、医疗兵。每位玩家至少尝试同一干员的两种E路线；先保持枪械、配件和G一致，以便判断变化来自E及成长组合，再独立更换该干员专属G。G仅可从本干员三种中选一，不能跨职业装备或交换。交替尝试团队交火和据点模式。记录实际选择，不强求抽齐预定四张牌。

建议先2v2学习操作，再4v4观察团队效应；不足真人席位可用机器人补位，但记录真实人数并单列混合场，不能记为8真人。标准与短局分别统计。八条路线为：突击翻滚/突进装填，重装屏障/定向盾，狙击专注/战术转移，医疗脉冲/治疗链。

重点观察：是否知道何时能选卡；能否在交火、死亡和网络延迟期间完成选择；选卡理由是否与当前局势有关；坦克推进/据守、狙击守线/转移、突击推进/控枪是否产生不同决策。Medic 额外检查是否能找到受伤队友、治疗反馈是否明确。

## 第二轮：替代项、配件与再次构筑

根据第一轮问题调整后再进行，明确记录新版本。当前竞技枪械、配件、卡牌侧向开放，账号经验不提供战斗数值优势；不需要管理工具解锁。进化由局内第四次选择及前置两卡决定，没有战前进化开关。将新构筑与基础构筑对照，记录收益发生在什么情境、代价是否确实影响选择，以及是否存在明显无条件更优选项。

专项轮换覆盖12种专属G，记录使用或未使用的理由。安排双医疗、双重装，以及烟雾/信标/EMP/拦截器同场，观察治疗反馈、阵地拆除与信息可读性。固定轮换场用于验证操作，另留自由选装场观察偏好；配件选择集中度只统计自由选装场。

建议两轮累计至少20局；没有足够数据时继续标记“待验证”。不要以小样本胜率宣称平衡完成，也不要把尚未开展的第二轮写为已完成。

## 汇总与验收

服务器 JSON Lines 日志包含 `growth.playtest_result`，可在项目根目录运行：

```powershell
npx tsx tools/growth-playtest-report.ts <服务器日志路径> artifacts/qa/growth-playtest-report.json
```

报告v2支持旧卡及成长v3的48普通卡、8进化卡，兼容日志的`content`和历史`contentVersion`；两字段冲突时拒绝该行。按内容版本、地图、模式、标准/短局分组，并分离含机器人场与无机器人席位，统计每职业每席位选择频率、选卡平均/P95耗时、局末等级差及经验。不输出账号或actor身份。无机器人席位仍可能是脚本，因此真人数量必须由组织者另行确认；缺少场景字段的旧日志归unknown，不猜测场景。

选卡频率的分母是该职业参赛席位数，不是候选出现次数；现有日志没有记录所有未选候选。局末等级差包含已离场者，不等于整局平均等级差。

重复导入同一行或仅JSON字段顺序不同的同义副本只统计一次；去重包含版本、房间/局次/时间、地图/模式/预设、机器人数量及玩家统计，不跨这些维度合并场次。不要人工改写时间等字段后再次导入并当作新试局。

当前结果日志不含玩家熟练度、枪械配件选装和请求/前摇终态明细；这些列须由组织者记录，缺失填“未记录”，不可填0。手工观察到的失败次数不当作精确失败率。QA机器人观察器的计数也不能并入真人日志。将逐局反馈与报告按内容版本、地图、模式、预设对应后再提出调参建议。

结合每局反馈逐项确认四个问题，列出未解决问题、关联版本及下一轮验证方式。机械隔离另有 `npx tsx tools/growth-balance-audit.ts`：它证明同构筑的账号等级隔离和配件存在数值取舍，不能证明真人对局中的等效胜率。
