## 2026-09-11 账号、职业与养成

沿用单机目标做本机账号，各账号独立保存关卡、军资和职业成长；首次注册只迁移一次旧匿名战役，不删除原存档。采用Web Crypto随机盐PBKDF2密码校验，sessionStorage记住当前标签页登录，不实现网络身份认证。

以原作Medic/Assassin/Commando/Tank及技能方向为参考，做四职业独立升级和配装。八种主动技能、七种枪械、三种战术道具按四关游戏重新调配。永久购买跨职业共享，装备受当前职业等级限制；主动退出未结束比赛不发奖励，终局奖励去重。

只读静态参考资料，未运行原作。新的技能、经济、手雷及数值属于本项目设计，不升级原版证据分类。

## 2026-09-11 四关原创单人短篇

按用户持续目标推进Phase4—6。单人剧情玩法采用简报串联的小队竞技任务，而非线性清怪跑酷：四关包括1v1、2v2、据点和3v3，有胜负、复活、结局与本地解锁。关卡、剧情与矢量美术原创。只按需阅读已有Stats_Campaign/MatchSettings静态资料，没有运行参考SWF。

战役默认入口与训练场分开。复用OriginalMovement、OriginalLife、GunController、Recoil、traceBulletLine；Arsenal只适配多角色，不改动训练场。难度通过反应/瞄准误差表现，不改变生命或伤害。新增跳跃事件缓冲避免短按丢失；同时保留暂停清输入与复活扳机锁。生产资源与纯Node本地服务器打包，游玩不依赖Vite或外部网络。

## 2026-09-11 自研方向与 Phase 3 收尾

用户明确将目标从完全复刻转为基于已有机制打造自己的游戏，优先迭代现有实现。此决策替代下方历史“原版规则优先于游戏设计”的强制要求。反编译仅作按需参考；确需运行老游戏或逐帧分析时先询问用户。本轮未启动参考运行器。

默认使用已整合的30Hz沙盒，旧实验室显式入口保留。保留Original模块名称以减少无关重命名；新增反馈、关卡死亡边界与复活清理是自研选择。原版证据分类不变。工程闭环完成不代表主观手感或逐帧一致性已经验证。

## 2026-09-09 Phase 1 与验证

- 直接使用 Phaser 3.90、TypeScript 和 Vite；未接 OpenGame 服务，没有引入未来战斗系统的空模块。
- Phaser 的自动物理循环与手动 120 Hz 循环不能叠加。通过 disableUpdate 禁用自动更新，每步明确 preUpdate、控制、resetFlags、step、postUpdate，实际浏览器测试验证 30/60/144 Hz 显示条件下一致。
- 台阶前探增加空间占用检查，18 px 默认上限拒绝 28 px 台阶；单向平台用下降方向、上步脚底和下穿计时器过滤。
- 所有 14 个初始运动参数进入 TUNED 证据记录；测试防止配置与证据库漂移。
- 将 Vitest 升到 4.1.11 修复依赖审计问题。npm 10 在更新可选 peer 图时出错，更新时采用 legacy-peer-deps，随后普通 npm ci 已验证成功，无需用户设置全局 npm 选项。
- 验证结果：14 项规则/工具/证据测试、7 项 Chromium 游戏集成测试通过，TypeScript 和生产构建通过，npm audit 0 vulnerabilities。
- Phaser 独立 vendor chunk 约 1.21 MB（gzip 332 KB），构建给出体积提示；这是当前完整引擎体积，不影响本地移动实验室验收。以后有真实性能需求时再评估定制引擎构建。
