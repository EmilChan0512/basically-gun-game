2026-09-10 后续更正：当前换弹键为L，R重置士兵；有效开火只有命中存活目标才产生DamageEvent，空枪仍消耗弹药。Phase 3已按原版P-code修正备用弹药、换弹和切枪规则，换弹期间保留剩余弹匣子弹；下面早期切片中“换弹显示为空”是已被替换的实验设计。最新行为见 [COMBAT.md](COMBAT.md)。

## 目标

Phase 2 交付一个可测量的单人射击实验室，验证 `Fire → ammo/cooldown → ray → DamageEvent → health → death → score → respawn` 闭环。它不是完整对战、机器人或最终美术实现。

## 证据边界

USP 的伤害 15、弹匣 12、半自动属性来自 `REFERENCE_FINDINGS.md` 的 `EXTRACTED` 记录。250 ms 冷却是当前实验映射，标为 `INFERRED/TUNED`，直到原版运行观测完成不得宣称为历史实测。目标生命值、射线距离、得分规则和复活时间属于实验配置。

## 交付范围

- 鼠标瞄准线和明确的开火输入（鼠标左键 / F）。
- 静态训练目标，显示命中、生命值、死亡和复活。
- USP 弹药、冷却、空弹匣和重装（R）。
- HUD 显示武器、弹药、冷却、目标生命值和得分。
- 纯 TypeScript Combat 状态层，渲染与规则分离。
- 单元测试覆盖冷却、弹药、伤害、死亡和复活；浏览器测试覆盖实际输入与 HUD。

## 验收门槛

1. 同一时间步内冷却阻止重复开火。
2. 每次有效开火只消耗一发弹药并产生一个 `DamageEvent`。
3. 目标生命值归零后进入死亡态，复活时间到达后恢复满血。
4. 重新加载页面后 Phase 1 运动验收保持通过。
5. 所有未从原版核实的数值继续标注为 `TUNED` 或 `INFERRED`。
