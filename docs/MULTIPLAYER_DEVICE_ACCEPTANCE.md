## 启动与连接

从Git拉取源码验收时，先安装Node.js 22.12+，在项目目录执行`git pull --ff-only`和`npm ci`。使用`npm run dev`启动客户端，按终端给出的地址打开并加上`?online`。另开PowerShell窗口，在项目目录执行`$env:HOST='0.0.0.0'`后执行`npm run server`，再按下方步骤填写服务器电脑的局域网IP。单机试玩直接打开客户端地址即可。

如需离线分发包，执行`npm run package:game`及`npm run package:server`，之后按以下包启动步骤操作。`artifacts/`是本机生成目录，不随Git提交；文档中的历史报告及ZIP路径不保证在新设备存在。运行游戏不需要原游戏SWF、反编译工具或重新提取资源，所需运行时图片和地图数据随源码提交。

1. 在服务器电脑安装Node.js 22.12+，使用与客户端相同批次的`project-strike-server`包。PowerShell进入包目录，运行`$env:HOST='0.0.0.0'`，再运行`node server.cjs`。默认端口4180，按需允许局域网访问。
2. 两台或更多客户端电脑各自启动`project-strike-local/PLAY.cmd`，打开`http://127.0.0.1:4175/?online`。服务器栏填写服务器电脑的实际局域网IP，例如`ws://192.168.1.10:4180`。不要填写另一台电脑的127.0.0.1。
3. 一人创建房间，其他人填写显示的房间码加入。不同浏览器页面代表独立玩家，总席位上限8，包含观战者。选择地图/模式后，各自设置配装并准备，由房主开局。
4. 测试完关闭服务器；临时房间不会持久化。本机战役存档仍保存在各自浏览器的原地址/端口，不与联机装备或合作记录混算。

公网测试另需可达地址及TLS反向代理；HTTPS页面使用wss。本文不代表已经部署公网服务。

## 每次测试的证据

记录日期、客户端/服务器包内容版本、CPU/GPU/内存、浏览器版本、物理设备数量、每设备客户端数量、网络类型、地图/模式/配装、时长和最终比分。截图或录屏应包含问题发生前后的操作；失败记录写明复现步骤，不用“基本正常”代替验收结果。
