## 初次审查基线（下列问题部分已修复）

本节记录改造前的代码状态，不能用作当前缺陷清单。当前实现已包括Battle.tickPlayers独立输入、Checkpoint、ModeRules及权威服务器；剩余限制见上方阶段出口。保留基线用于解释拆分原因。

- `src/game/campaign/Battle.ts`：tick只接收一份BattleInput，所有human角色读同一输入；jumpHeld只有一个；player固定actors[0]；swap/reload/releaseInput围绕本地玩家。必须改为playerId/actorId关联输入，独立按键边沿。
- Battle胜负是相对于蓝队的won/lost，模式分支和AI目标写在同一类中；多人需要中立MatchResult，再由客户端解释胜负。客户端Esc只能打开菜单，不能暂停服务器。
- Battle可以注入随机函数，但默认Math.random，创建ID用crypto.randomUUID；现有snapshot是HUD/测试摘要，不含完整朝向、所有装备计时、输入确认、随机状态、目标携带状态等，不支持恢复。不可直接当网络协议或回滚存档。
- `Missions.ts`把剧情、模式、地图、人数混在一起，地图为矩形实体地形，宽1800/地面600的假设散落；出生点每队仅3个。单纯提高人数会重叠出生。`Navigation.ts`为小图路径图，需要动作边与可达性校验。
- `Arsenal.ts`所有装备都创建GunController，不能用伤害为0的枪代替盾；`Ballistics.ts`当前命中类型没有盾，近战/特殊投射物仍在现切片之外。
- `Catalog.ts`同时含规则与展示信息，类型使用封闭武器ID；`ReferenceArt.ts`硬编码资源列表及部分枪长，军械库假设PNG枪械图。增加内容要同时更新规则、展示、存档校验，需统一注册表。
- `Accounts.ts`与CareerProgress是本机身份与本地养成，不能充当在线身份验证或权威装备来源。`tools/serve-game.mjs`只是127.0.0.1静态服务器，不是联机服务。

## 目标模块边界

```text
内容：MapDefinition / ModeDefinition / EquipmentDefinition / PvEScenario
                         ↓
共享规则核心 MatchSimulation（30Hz，无DOM/Phaser/存储）
        ↑ Commands                 ↓ State + Events
本地Session适配器              服务端RoomSession（权威）
        ↓                         ↕ WebSocket
        └────────── 客户端Session接口 ──────────┐
                          ↓                   │
                  RenderState / HUD / 雷达 / 声音
                          ↑
                  Phaser + DOM表现层
```

建议增量目录：`src/shared/simulation`、`src/shared/content`、`src/shared/protocol`、`src/client/session`、`src/client/presentation`、`server/rooms`。可先从campaign目录抽模块，不先做大规模机械搬迁；不引入通用ECS作为前置条件。

协议至少区分：版本化MatchConfig（地图/内容哈希、模式、队伍、人数、配装策略、seed），PlayerCommand（玩家绑定、序列号、移动/瞄准/动作），网络快照（服务器tick、各玩家已处理序号、可见状态、事件序号），完整内部Checkpoint（全部模拟状态，供恢复/测试，不直接广播）。客户端不能提交坐标、伤害、得分或奖励结果。

## 阶段A：多人可用的本地规则核心

交付：将Battle逐步拆为MatchSimulation、输入控制、模式规则、AI控制和结果对象；离线战役通过LocalSession继续运行。以actorId维护输入、jump/fire边沿、换枪/技能/道具命令。真人与AI都生成同格式命令，每tick固定顺序消费；actor的控制归属与team分离。

注入可记录状态的随机源、ID和tick时钟。明确序列化/恢复所有影响下一帧的状态：移动计时、所有武器冷却与换弹、生命/技能、手雷、输入边沿、AI状态、模式目标及RNG。分开Checkpoint与渲染快照，建立单向事件流，事件去重避免校正时重复声音/奖励。

验收：8个独立输入源互不串键；同seed+命令录制在同运行时重放结果相同；保存后恢复继续模拟结果一致；核心能在Node无浏览器运行；原战役/训练场/存档回归通过。此阶段不宣称跨平台浮点锁步，也不要求所有客户端完整模拟整局。

## 阶段B：地图与模式分离，交付失控飞机

交付：MapDefinition定义独立ID/版本、世界边界、碰撞、出生区域、导航、补给、模式目标插槽、美术层和缩略图；Mission只引用地图ID、模式配置和剧情。模式声明所需插槽，不兼容地图禁止选择并说明缺什么。地图选择用于自定义对局/房间，原战役仍固定剧情地图。

碰撞从wallFor提升为CollisionWorld接口；先支持现有矩形，飞机如需位图掩码/复杂轮廓则适配同一接口，服务器只载碰撞数据，不加载纹理。消除固定高度/坠落界限假设；出生区域至少容纳4v4或8人合作，包含安全距离、失败回退和短暂保护。导航记录walk/jump/drop等有向边；复杂动态地形仅在静态证据确认需要时加入。

飞机参考证据：`archaeology/exported/scripts/Stats_Maps.as`中plane名称Hijack，plane2名称Hijack (Dawn)，共用map=plane。当前已将Hijack接入为“失控飞机”，静态提取原美术、碰撞掩码与导航并验证240组平台路线；本游戏坠落阈值等适配值不冒称原版数值。完整原图不等于碰撞数据，后续动态效果按实际需要另行核对。

验收：现有地图迁移无行为变化；菜单可选飞机并实际游玩；8人出生无堆叠卡死；双向穿行、坠落复活、上下层射线遮挡、AI抵达目标可验证；客户端/服务端地图哈希一致。输出地图预览和碰撞/导航调试图。无需运行老游戏，只有静态资料不足且确有必要时先问用户。

## 阶段C：8人联机PvP最小闭环

交付：独立Node权威服务器、WebSocket传输、创建/加入房间、准备、队伍分配、地图/模式选择、开局/终局/返回房间。首版TDM 4v4和现有占点；加入人数由服务器上限约束，开局后新玩家先观战，断线原玩家支持短时重连。

服务器30Hz固定步；快照初始目标15–20Hz，实测后调节。客户端本地移动预测、输入序号确认与未确认输入重放、远端角色插值；生命/弹药/目标/积分最终以服务器为准。射击表现可立即反馈但命中确认由服务器发事件。明确延迟补偿窗口：初始建议最多150ms历史命中盒回溯，由服务器校验时间戳并限制，不能相信客户端宣称的射击时间；静态墙与历史目标一致处理。

加入时校验协议、地图和装备版本。限制输入频率、有限数值、命令长度与未来tick；玩家只能控制绑定角色。丢失输入短时保持移动，超时清零，离散动作按序号仅执行一次。重连以完整基线覆盖本地预测；默认30秒重连保留席位，超时离场，队伍人数/弃权规则显式配置。服务器退出则房间结束，首版不做主机迁移。

在线身份先用服务器签发的临时会话/重连令牌，独立于本地账号。PvP默认统一等级/训练值并使用房间允许装备，服务器校验；不把客户端本地军资和等级作为竞技依据。不在本阶段增加云养成后端。互联网试玩需要可达服务器与HTTPS/WSS部署，开发机localhost只用于本机验证；上线部署是后续具体交付，不由当前文档执行。

验收：至少两台设备、总计8客户端完成整局；第9人被拒绝；房主退出、断线重连、协议不匹配均可恢复/提示；菜单不暂停别人；伪造坐标/伤害无效。模拟50/100/150ms RTT、抖动和丢包/重传压力，检查重复动作、瞬移、命中确认与事件一致性。记录8客户端下tick耗时、快照带宽、客户端帧率及预测修正分布，未达标不进入内容批量扩充。

## 阶段D：多人PvE

交付：复用同一服务器与核心，增加CoopMode、WaveDirector和PvEScenario，支持1–8真人同队、AI敌方、波次/任务目标/结算。人类上限与AI预算分开；初始基准为8真人+16活跃敌人，性能不够先优化AI频率/感知缓存再扩敌群。

AI策略分层：导演负责刷怪节奏/预算，机器人负责导航/目标/战斗；不能靠修改坐标穿越。导航/感知可分帧，攻击与命中仍在30Hz规则执行。难度按开局人数分档并封顶，不简单将血量乘8。首版采用有限团队复活次数，全部阵亡且无复活机会判负；中途断线不立即降低当前波强度，下一波调整。

验收：单人保留开局、波次推进、死亡/复活、失败结算与记录等基础检查，不要求脚本自然通关；4/8玩家验证胜负流程；断线不会锁死波次；刷怪有可达点且不在玩家身上；地图选择仅列出有PvE出生/目标插槽的地图；性能报告覆盖8+16负载。合作奖励首版明确留在本地独立记录，不伪称防篡改在线经济。

## 阶段E：雷达与公文包目标模式

雷达交付：静态地形底图、自己/队友/目标、模式相关敌人标记。坐标从地图bounds统一投影，支持长飞机地图和上下层；更新独立于模拟，UI缩放不影响位置。先定义RevealPolicy：队友与公开目标常显，敌人默认仅在视野/开火暴露窗口出现，隐身依规则隐藏。服务器按接收者过滤非公开信息；仅从雷达隐藏但仍广播完整秘密状态不算信息隔离。客户端预测只用公开碰撞/自身状态，不能因过滤实体导致本地参与权威伤害计算。

公文包交付：模式插件而非写入Battle的大段分支。首版状态为atBase/carried，记录载体、归属、位置与事件ID；拾取、运送、交付、死亡/越界/离场立即复位都由服务器裁决。同tick多人接触按稳定角色ID顺序只允许一人拾取；得分事件仅一次，重连不复制公文包。AI增加取包/护送/拦截/回防目标选择。dropped/returning作为未来变体预留，不是原版首发要求。

静态核对结果见[公文包规则表](BRIEFCASE_RULES.md)：Stats_Misc、NodeCtfFlag、Unit、Guns和MatchSettings确认双方目标运送+1分、默认3分、携带者死亡立即复位、己方目标不在家仍能交付、携带限制副手。flag1/flag2对应的原蓝/橙公文包资源已核对并接入。不能把它等同于持有持续得分或单包争夺；后两者是未来不同模式。

验收：8人争夺、同时拾取/交付、死亡/坠落/退出、时间结束和平分都有可复现结果；雷达与世界目标同源；隐身和暴露窗口测试通过；飞机提供对应目标点后可选择该模式。

## 阶段F：装备扩充、刀与盾

交付：统一EquipmentDefinition，区分firearm/melee/shield，包含槽位、行为、表现资源和规则版本；Loadout的副手可选枪/刀/盾。射线枪复用现有GunController；刀使用攻击前摇/有效窗/后摇和范围/扇区/墙体检测，每次挥击同目标只命中一次。盾使用朝向、防御扇区、耐久和部署/收起状态，明确背后攻击、爆炸和近战绕防规则；这些数值属于本游戏设计，不默认宣称原版值。

伤害入口改为DamageContext（来源、命中点、方向、伤害类型、攻击ID），统一经过盾拦截、职业修正、生命扣除和模式击杀事件。先规定副手切换互斥，不默认支持枪盾同时用；之后通过兼容表扩展。抽出装备表现注册，消除ReferenceArt的枪型条件，缺图在开发期报错，运行期有明确回退。

同步更新服务端配装校验、HUD、军械库、雷达暴露规则、AI装备使用与存档版本迁移；旧USP副手自然映射到firearm。新增枪优先使用已导出时间轴资源；确有缺图时才建立本机ComfyUI工作流，固定尺寸、拆件、种子及来源。

验收：不同副手切换不会绕过冷却；挥刀不穿墙/重复命中；盾前后方向在网络延迟和复活后正确；旧存档可读，未知ID安全回退；8人混合装备及PvE回归通过。新增普通枪通过注册内容完成，不需再次修改MatchSimulation。

## 阶段G：综合验收与发布候选

组合矩阵覆盖：2/4/8人PvP、1/4/8人PvE；飞机和现有地图；TDM/占点/确认后的公文包；枪/刀/盾；死亡重连/切局/旧存档。只允许地图×模式兼容矩阵中的组合。

建议验收预算（目标，尚非测得结果）：约定一台4核参考服务器，8人PvP及8+16 PvE的模拟tick p95<10ms、p99<33.3ms；至少10分钟运行无明显积压/内存异常（用户已取消30分钟要求）；参考客户端1080p目标60fps，另录低端设备表现；每客户端平均下行初始目标<100KB/s。记录硬件、浏览器、模式、地图和网络条件，超过预算先定位再定容量，不承诺未测过的并发房间数。

交付独立客户端离线包、服务器运行包、部署/房间操作说明、版本兼容与故障恢复说明、性能与玩法验收报告。离线仍可单机游玩，在线连接失败不覆盖本地存档。
