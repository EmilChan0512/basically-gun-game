# 用户权益管理后台

生产入口：`http://43.142.165.82:4180/admin/`。使用独立管理员账号，不接受游戏账号登录。管理员原始密码保存在部署操作者本机的 `artifacts/private/管理员后台.md`，不进入源码或安装包。

在左侧搜索用户名或完整用户 ID，选择用户后可以设置金币（0—10000000）、各职业等级（1—50），授予或收回枪械及战术道具。刀盾和技能继续按职业等级解锁。初始枪械及急救包不可移除。提供四职业满级、授予全部装备、仅保留初始装备按钮。

填写修改原因，点击“预览并保存修改”，核对用户名、金币、等级、装备增减后确认保存。页面展示最近 100 条资产记录，管理员记录可展开查看修改前后完整资产；全部记录保留在服务器账号数据库中。

保存时，服务端检查客户端读取时的资产版本。如果期间发生购买、奖励或其他修改，返回冲突并要求刷新，不覆盖新增资产。等级未变化时保留该职业的零散经验，改变等级则设置为该等级起始经验。不再符合等级或持有条件的配装槽位自动恢复为初始装备。

修改完成后注销目标用户的登录会话和重连席位，并结束其当前连接。用户重新登录即可使用新权益。其他用户账号和管理员会话不受影响。

## 存储和部署

后台 HTTP 与游戏 WebSocket 共用 4180 端口，运行于同一服务、同一 `OnlineAccounts` 实例。资产及审计日志一起原子保存到 `/var/lib/project-strike/accounts.json`。不得另开一个进程并行编辑同一个账号文件。

管理员配置独立保存于 `/var/lib/project-strike/admin.json`，所有者 `strike`，权限 `0600`。内容为 `username`、32 位十六进制 `salt`、128 位十六进制 scrypt `verifier`、完整 `origin`（无尾斜杠），不保存原始密码。缺少此文件时后台不启用；配置损坏则拒绝启动。

部署顺序：先通过 Backend CI and deploy 发布包含后台的程序，再运行 Configure administrator access 工作流。其临时 secret `ADMIN_BOOTSTRAP` 放上述配置 JSON；脚本使用生产部署锁、备份旧配置、安装并重启、检查后台与游戏健康。完成后删除临时 secret。更换密码可用新盐和哈希重新执行此流程，重启会清除全部管理员会话。配置文件在版本升级时保留。

管理员使用四小时有效的 HttpOnly / SameSite=Strict Cookie；写接口还检查 Origin 和会话 CSRF Token，限制登录频率和请求体大小。用户名、密码、哈希和会话令牌不写入应用日志。配置 HTTPS origin 时 Cookie 自动加 Secure；后续使用 HTTPS 反向代理时同步修改 origin。当前按项目已批准的无域名兼容方案使用 HTTP。

验证：`npx vitest run tests/unit/admin.test.ts` 和 `npx playwright test tests/gameplay/admin.spec.ts`。涵盖鉴权、跨站请求拒绝、并发编辑冲突、持久化审计、等级降级和装备撤销、在线会话失效及桌面/手机操作。
